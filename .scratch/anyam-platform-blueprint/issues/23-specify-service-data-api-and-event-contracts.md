# Specify service, data, API, and event contracts

Type: prototype
Status: open
Blocked by: 08, 12, 13, 15, 20, 22

## Question

Which bounded contexts and authoritative state machines should exist, how do they communicate, and what stable REST, SDK, MCP, webhook, event, idempotency, concurrency, pagination, and error contracts do clients consume? Produce an implementation-level logical architecture and representative schemas without prematurely binding every context to a separate deployed service.
