# ADR 0104: Real-team adoption evidence gate

Status: Accepted

Issue: [#286](https://github.com/Whyme-Labs/anyam/issues/286)

## Context

Local fixtures and `npm run qualification:team-simulation` prove product seams,
not human adoption, customer-account operation, production reliability, or
security assurance. The final Wayfinder ticket requires a named cohort and
receipts that cannot be generated by an agent acting alone.

## Decision

The owner-controlled evidence bundle uses protocol
`anyam.real-team-adoption-gate/v1` and is validated by
`npm run qualification:real-team-gate -- path/to/evidence.json`.

The validator fails closed unless it contains:

- 3–10 named human participants, two coding-agent products, a
  customer-operated Anyam-canonical Realm, and a 30-calendar-day window;
- at least 25 named terminal Changes;
- verified receipts for ordinary Git, concurrent Workspaces, Intent and Pull
  Request lifecycle, review/Landing, conflict/rebase, hybrid projection,
  bidirectional GitHub projection, export/restore, and no canonical write;
- a verified customer-owned Worker Release/Target provider receipt;
- verified sustained-load, queue-recovery, Durable Object contention,
  backup/restore RPO/RTO, authentication throttling, key rotation, incident
  alerting, and independent security-review receipts; and
- an explicit team retention decision of `continue`.

Every receipt names an owner, observation time, next action, and credential-free
receipt text. `not-verified` and `indeterminate` remain blockers. The validator
does not accept the local team simulation as a substitute for the human or
provider evidence.

## Consequences

- The exact human-only boundary is executable and reviewable instead of living
  in prose or an informal checklist.
- Anyam can be re-evaluated after the 30-day trial without changing the gate
  contract.
- Until an owner supplies the named cohort and evidence bundle, #286 remains
  open and the public-beta/production claim remains blocked.
